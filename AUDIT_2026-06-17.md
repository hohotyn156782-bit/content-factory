# Итоговый отчёт аудита: content-factory

## 1. Оценка готовности к production: ~55%

**Обоснование.** Ядро пайплайна (генерация сценария → озвучка → b-roll → сборка → QA-гейт) укреплено и работоспособно: логи, http-повторы, WAL+busy_timeout в `topics_db`, RLock в истории, QA-гейт на ручной публикации. Это даёт прочную базу. Однако **система не является автономной фабрикой, как заявлено**: автопилот физически не запущен, а на автономном пути разорваны цепочка публикации статусов и петля обратной связи аналитики. Плюс несколько путей публикации (Threads, текстовый VK, VK-видео, factory.py CLI) либо молча не работают, либо публикуют ложный «published». До закрытия блокеров система не способна крутиться 24/7 без оператора.

Снимаю с оценки: -25% за неработающую автономность (критический + 2 high), -15% за дефекты публикации (4 high), -5% за разрыв feedback-loop.

## 2. КРИТИЧНЫЕ блокеры (must-fix)

### B1. Автопилот не запущен — система не крутится 24/7 *(critical)*
`panel/scheduler.py:1-15` (docstring), crontab.
**Проверено:** `crontab -l | grep scheduler` → пусто (exit 1). `morning()/tick()` никем не вызываются.
**Фикс:** установить cron из docstring с `CRON_TZ=Europe/Moscow`, `flock` на tick и путём секретов `~/.config/content-engine/secrets.env`. Без этого вся остальная автоматизация мертва.

### B2. Цикл аналитики разорван на автономном пути *(high)*
`panel/scheduler.py:177` vs `pipeline/analytics.py:117`.
**Проверено:** `tick()` при `ok=True` делает только `update_plan_item(status="posted")`, НЕ выставляет `content.status` и `targets.url`; а `collect()` читает только статусы `("published","partial","pending_manual")` → метрики никогда не снимаются на cron-пути.
**Фикс:** в `tick()` после успешного постинга зеркалировать ручной путь `server.py:278-291` — собрать targets и `db.set_targets(content_id, tg, cstatus)`.

### B3. Нет мониторинга/алертов о падении *(high)*
`reporter.py:24`, `panel/scheduler.py` (нет `import reporter`).
**Фикс:** обернуть `__main__` scheduler в try/except → `reporter.send("🛑 Автопилот упал: ...")`; слать сводку в конце `morning()/tick()`; алерт при `posted==0` при наличии ready-слотов. Без этого тихий отказ автономной фабрики не будет замечен.

### B4. Публикация ломается на нескольких площадках *(4× high — суть одна: маршрутизация публикации)*
- **Threads вообще не публикуется** — `_adapter()` не знает `threads` (проверено: `panel/server.py:226-237`, ветки нет → `None` → немой AttributeError).
- **Текстовые площадки (Threads/VK kind=text) идут через video-publish** вместо `publish_text` (`server.py:275-279`).
- **VK-видео заливается community-токеном**, который `video.save` не принимает → реальная публикация видео в VK сломана (`adapters/vk_video.py:71-93`; проверено: токен берётся из `secret_token` community).
- **factory.py CLI постит без QA-гейта и без account** (проверено: `_post_dir` `factory.py:122-147` сразу зовёт `adapter.publish` без проверки `meta.qa.ok` и без передачи связки → VK уходит community-токеном мимо панели).

**Фикс (минимальный):** (а) добавить ветку `threads` в `_adapter`; (б) для `kind=='text'` исключить площадку из `_seed_targets` либо звать `publish_text`; (в) завести отдельный `VK_USER_TOKEN` для `video.save`; (г) добавить в `_post_dir` тот же QA-гейт и проброс account, что в `api_publish`.

## 4. Остальное по темам (кратко)

## 🔍 Что аудит мог пропустить (критик полноты)

I have all evidence needed. Here are the gaps the audit missed.

---

Аудит был силён по infra/concurrency/publishing-маршрутизации, но почти не тронул то, что для faceless-видео-фабрики решает выживание: уникальность контента между роликами, AI-разметку площадок, слепоту feedback-loop на 3 из 5 площадок и реальный потолок квот. Вот 5 конкретных упущенных рисков, каждый с доказательством из кода.

## 1. Feedback-loop физически слеп к 3 из 5 площадок → веса ниш перекошены
`pipeline/analytics.py:88` — `_FETCHERS = {"youtube": _youtube_metrics, "vk": _vk_metrics}`. **Нет фетчеров для TikTok, Instagram, Threads.** В `collect()` (строки 121-124) для этих платформ `metrics_for` всегда возвращает `None` → снапшот не пишется. Значит `recalibrate()` (`analytics.py:160`) считает средние просмотры ниши **только по YouTube+VK** — а это самые слабые/приватные каналы (YT до прохождения Compliance Audit вообще приватный, VK cap=1/день). Система будет «учиться» на нерепрезентативной выборке и душить ниши, которые на деле летят в TikTok/Reels. Аудит назвал разрыв feedback на cron-пути (B2), но НЕ заметил, что даже на ручном пути петля видит максимум 40% площадок. Где смотреть: `analytics.py:88, 121-130`.

## 2. AI-контент не размечается через API ни на одной площадке → теневой бан / демонетизация
AI-раскрытие существует только как текст в описании (`pipeline/build.py:51`: `"Создано с помощью ИИ. "`). Но обязательные **программные флаги не выставляются**: YouTube `status.containsSyntheticMedia` отсутствует в `youtube.py:73` (там только `selfDeclaredMadeForKids`), у TikTok нет AIGC-флага, у Instagram/Threads нет AI-label-параметра. При том, что весь b-roll — FLUX-картинки + DepthFlow (`broll.py:163-201`), а в `business_stories`/`mystic_stories`/`psy_stories` ещё и синтетический голос. С 2026 площадки сами детектят синтетику и понижают/снимают монетизацию за нераскрытие через API. Где смотреть: `adapters/youtube.py:70-74`, `adapters/tiktok.py`, `adapters/instagram.py`, `adapters/threads.py`.

## 3. B-roll не дедуплицируется МЕЖДУ роликами → дубль-контент-страйки и визуальная сериальность
`broll.py:228` — `used: set = set()` создаётся заново на каждый вызов `fetch_for`. Это дедуп только внутри одного видео. Между видео той же ниши Pexels по одному и тому же `broll_hint` (напр. `money_facts`: «money, coins, stock market chart») будет отдавать **те же топ-клипы**. Топик-антиповтор есть (`topics_db.py`), но визуальные клипы нигде не трекаются между сборками (grep по `build.py`/`topics_db.py` не нашёл ни одного persistent-стора использованных `pexels_id`/`source_url`). Для YT Shorts/Reels повторяющийся видеоряд = «unoriginal/repetitious content» → отказ в монетизации и алго-пессимизация. Где смотреть: `broll.py:228, 252-264` (ветка `reuse` вообще берёт уже скачанное по кругу).

## 4. Фолбэк-озвучка схлопывает все ниши в 1-2 голоса → аудио-сериальность всего каталога
Все 12 ниш в `niches.json` стоят на `"engine": "elevenlabs"` (строки 10,58,101,143,186,229,...). ElevenLabs free-tier — ~10k символов/мес на ключ; при исчерпании ключ уходит в 6-часовой cooldown (`voice.py:192`) и `synthesize` падает на edge с **захардкоженным** голосом: `ru-RU-SvetlanaNeural`/`ru-RU-DmitryNeural` (voice.py фолбэк-ветка, строки ~14-20 от `synthesize`). То есть как только free-квота EL кончится (а на 5 ниш × несколько роликов/день это произойдёт за дни), **весь русский каталог зазвучит одним из двух голосов** — потеря узнаваемости каналов и ещё один сигнал «штамповки». Голос из niches.json («Adam»/«Sarah») при этом для edge не используется — фолбэк его игнорирует. Где смотреть: `pipeline/voice.py` (тело `synthesize`, ветки elevenlabs→edge), `niches.json` voice/engine.

## 5. Нет дневного бюджета на генерацию изображений → потолок квот FLUX/NVIDIA непредсказуем
В режиме `ai_images`/`depth_video` каждый ролик дёргает `imagegen.generate` 6-9 раз (по слоту, `broll.py:233-250`). Cooldown ключей NVIDIA/Gemini хранится в in-memory `_COOLDOWN` (`imagegen.py:65,94`) — бесполезен при per-build процессах (аудит это отметил для текстовых LLM, но НЕ для картинок). **Нет ни одного persistent-счётчика сгенерированных за день картинок.** На 5 ниш × N роликов × 7 кадров фабрика молча упрётся в дневной лимит NVIDIA → каскад на Pollinations (медленнее, ниже качество, может 401) → визуальное качество деградирует посреди дня без сигнала. Аудит считал текстовые LLM-квоты (ТОП-10 #2), но не посчитал, что картинки — это в 6-9 раз больше вызовов на ролик и главная статья расхода. Где смотреть: `pipeline/imagegen.py:65,94,119-123` (нет дневного учёта), `broll.py:233-250` (множитель вызовов).
